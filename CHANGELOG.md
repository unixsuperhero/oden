## v0.1.0 (2026-10-25)

First tagged release. The core: inline commands and `<bin>-<sub>` executables on PATH merged into one `Catalog`, resolved by name, alias or unique prefix with recorded shadowing; `Cmd` handlers with `Ctx` input helpers; opt-in builtins (`help`, `info`, `version`, `which`, `commands`, `catalog`, `state`, `command`); `WithPrefixes` for extra external prefixes; the `o` family root bin. Standard library only. Since the untagged snapshots:

- Merge an inline command group with the same-named external (`BIN-NAME`, or `PREFIX-NAME` via `WithPrefixes`): the next word resolves over the union, exact before prefix, inline before the external on a name collision (the external's subcommand is listed as shadowed and stays reachable as `BIN-NAME SUB`); a prefix ambiguous across both sides lists both. External subcommands run as `BIN-NAME SUB ARGS...`. The external's subcommands come from its `catalog` or `commands --json` (2s timeout), cached in `$XDG_CACHE_HOME/oden` or `~/.cache/oden` by path, size and mtime; with no usable answer the group passes unknown words through. Group help lists both sides with their source; the parent row says `merges external PATH`; `Claim.Merged` and `Entry.Sub` are new. A non-group inline command still shadows a same-named external.
- Report an unknown command word as `BIN: command "WORD" not found` (`subcommand` below the root), a short `did you mean:` line (commands that are a prefix of the word, then close spellings), and the level's help, exit 1. Suggestions never resolve. Add `App.NotFound`, `App.Suggest` and `ErrNotFound`, which a `Default` returns to defer an unknown word to Run.
- Add declarative `Command.Children` groups with shared contextual help, parameter metadata, and application notes. Bare groups and `-h` / `--help` show the current subcommands without running handlers; `help COMMAND...` traverses the same catalogs.
- Add a shared human-facing `version` builtin reporting embedded module version, full commit SHA, commit time, dirty-build flag, Go version and module path; unavailable build metadata remains unknown.
- Separate usage into human and machine command groups, independently of optional domain categories.
- Preserve JSON-first `commands`, `catalog`, `state` and `command list/show/state`, including their established argument handling. No human-output flag is added.
- Add human-facing `info [COMMAND]`, optional `Command.Category` / `WithCategories`, and `Command.Audience` metadata. Builtin overrides inherit the builtin's audience unless explicitly set.
- Keep ochazuke's input-JSON protocol unchanged and document short aliases for application flags.
